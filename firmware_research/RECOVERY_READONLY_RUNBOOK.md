# R08 唯一设备恢复路径：只读验收清单

## 目的与边界

本清单用于证明：即使修改后的应用无法启动，也能通过不依赖 BLE 应用固件的入口识别芯片、读回所需区域，并最终恢复原状态。它不是拆机、焊接、擦除、写 Flash、写 OTP/eFuse 或刷候选镜像的授权。

当前只有一枚 `RT08_V3.1` 戒指。任何阶段只要焊盘身份、电压、工具行为或数据可恢复性不确定，就停止在该阶段，不用写命令“试一试”。

## 开始前必须取得的资料

- FCC `2AOM3-R08` 内部照片原始附件 `7833424`，应为 3 页 PDF；下载后先确认 `%PDF-` 文件头、页数和 SHA-256，Access Denied/Cloudflare HTML 不算照片。
- 用户自行登录 RealMCU 后下载的 RTL8762E 系列 SDK、MP Tool/MPCli 和对应版本文档。不要让用户发送账号、密码、cookie、token 或请求头。
- 戒指 PCB 高清正反面照片，需能看清芯片丝印、测试点、走线和电池焊点。拆机和拍摄前必须另行取得用户明确授权。
- 支持 1.8/3.3 V 可调逻辑电平的隔离 UART/SWD 工具、限流电源和万用表。未经原理图或测量确认，禁止向任意焊盘注入 5 V。

收到二进制工具或资料后，先记录来源 URL、文件长度、SHA-256 和软件版本；原件设为只读，分析副本与原件分开。官方 SDK/工具和 FCC 文件只保存在本地，不提交公开仓库。

## 当前恢复能力矩阵

这里的“通过”必须有目标戒指或等价可牺牲硬件上的可重复证据；文档存在、工具有按钮或文件能读出来都不算通过。

| 能力 | 当前状态 | 通过证据 |
| --- | --- | --- |
| PCB 与焊盘身份 | 未通过 | 目标 PCB 双面高清照片、走线/连续性和电压共同确认 P0_3、P3_0、P3_1、GND、供电 |
| 独立 MP/Boot ROM 入口 | 文档支持，未实测 | 应用损坏或不运行时仍可重复进入，只读退出后原应用正常 |
| Flash JEDEC ID/容量/保护状态 | 未通过 | 冷启动后至少两次只读结果一致 |
| 加密 Flash 分区读回 | 工具支持，目标未实测 | 完整区域表、两次独立读回、长度与 SHA-256 一致 |
| 读回数据可原样恢复 | 未通过 | 在非唯一等价目标上写回后冷启动，逐区校验并恢复全部功能 |
| 原厂完整重建包 | 未取得 | Bootloader、OTA Header、两个应用 bank、系统配置和持久化区均来源可追溯且可写 |
| OTA Bank Header 更新/选择与失败回滚 | 未通过 | 等价目标上的 bank 激活、掉电和运行时崩溃试验 |
| 双介质备份 | 未通过 | 可恢复数据而非仅应用 OTA 包，两个物理独立介质分别复核哈希 |

MP Tool 的 `Backup files` 仅复制当前配置的下载文件和 flash map；它不读取目标设备整片 Flash。RTL8762E 的 RD readback 是加密数据且不支持 `Read All`。因此“生成了 backup 文件”或“两次加密读回一致”最多证明可重复读取，不能把“读回数据可原样恢复”标为通过。

## 阶段 A：纯视觉和断电测量

1. 设备断电且电池隔离后拍摄 PCB 正反面、芯片顶标和所有测试点。
2. 根据封装资料只提出 P0_3、P3_0、P3_1、P1_0、P1_1、GND、VBAT 的候选焊盘；没有走线或连续性证据时保持“未确认”。
3. 用连续性档确认 GND；先测量再记录 VBAT 和各候选焊盘相对 GND 的静态电压。
4. 不焊接、不拉高/拉低、不上外部电源。若照片或测量不能唯一确定 UART trap/电平，阶段 A 失败并停止。

## 阶段 B：独立入口只读身份验证

1. 停止 Windows 戒指控制程序，完全退出手机 QRing；确保没有 BLE、OTA 或原始传感器会话。
2. 使用限流、正确逻辑电平和公共 GND连接 UART；不连接外部 VBAT，除非电源拓扑已被确认。
3. 仅按官方 RTL8762E 流程在复位时控制已确认的 P0_3，尝试进入 MP/Boot ROM 模式。
4. 首次只允许执行不会擦除或写入的芯片 ID、Flash JEDEC ID、容量和保护状态读取。保存完整控制台日志，但公开提交前脱敏。
5. 禁止 Download、Erase、Write、eFuse、OTP、Lock、Unlock、Set Address、DFU Start/Init/Data/Check/End。
6. 断开工具、正常复位，确认原应用仍能广播并报告精确硬件/固件版本。若进入过程改变了持久状态或应用不能恢复，停止全部后续步骤。

阶段 B 的通过条件：测试点和电平有证据；Boot ROM/MP 入口不依赖应用；Flash ID 与物理容量被重复读取且一致；整个过程没有任何写入。

## 阶段 C：双读一致性

1. 先从官方工具文档和实际只读帮助输出确认读回的地址单位、对齐、最大长度、是否自动解密，以及未指定区域的处理方式。
2. 建立完整区域表，至少覆盖 Bootloader/ROM 可配置区、OTA 元数据、两个应用槽、应用持久化区域、系统配置和工具报告的其他可恢复 Flash 区域。芯片内部 Mask ROM 不作为外部 Flash 读回目标。
3. 冷启动后读取第一份；完全退出工具并再次冷启动，读取第二份。不得在两次读取之间启动会修改 Flash 的官方 App 或应用功能。
4. 对每个区域比较长度和 SHA-256，再做逐字节比较。任何差异都必须先解释为计数器、日志、磨损均衡或工具包装；不能直接忽略。
5. 原始读回若为芯片绑定加密数据，标记为“尚未证明可恢复”，不能仅因两次相同就称为备份。

取得两份离线读回文件后，可用下列纯离线命令检查单一区域；必须按工具实际读取范围填写地址和长度，不能用推测值凑齐：

```powershell
py firmware_research\scripts\verify_r08_readback_pair.py cold-boot-a.bin cold-boot-b.bin `
  --base-address 0x0084E000 --expected-length 0x24000 `
  --region-name inactive-application-slot --encryption-status encrypted
```

校验器要求地址和长度均按 4 KiB 对齐、输入为两个不同文件，并同时检查声明长度、SHA-256 和逐字节差异。即使输出 `readback_repeatability_proven=true`，它也固定保持 `restore_proven=false`、`full_device_backup_proven=false` 和 `flash_authorized=false`；冷启动隔离、完整覆盖、独立介质及原样回写仍必须另行实证。

阶段 C 的通过条件：范围完整、两次读回一致、动态区域差异被定位、工具没有隐式写入，并且副本已保存到两个独立介质且各自重新校验。

## 阶段 D：回写与失败启动演练

此阶段不得在唯一戒指上首次执行。必须使用第二枚同硬件设备、厂商开发板或其他等价可牺牲目标，并确认其 Flash/封装/Boot ROM 行为一致。

需要依次证明：原样回写读回数据、恢复原厂应用、OTA Bank Header 更新/选择、not-ready/not-obsolete 状态变化、升级中掉电、应用结构有效但启动后崩溃、强制回到 Boot ROM，以及再次完整恢复。每一步都要有断电后的冷启动验证和哈希证据。

用户目前不购买第二枚设备，因此阶段 D 仍是硬阻塞项。不能把仿真、静态分析或“官方工具理论上支持”替代为真实恢复演练。

## 刷写候选前的最终判定

只有下列条件同时为真，候选构建器和文档才允许从 `NON_FLASHABLE` 改为受控试刷状态：

- 精确原厂应用镜像和完整设备恢复数据都有两个独立、校验一致的副本；
- 物理 Flash 容量、完整分区和所有恢复依赖已确认；
- 签名、加密、Secure Boot、反回滚和版本选择语义已确认；
- UART/MP 或 SWD 入口已在应用损坏时独立恢复成功；
- 候选在等价非唯一目标上通过写入、冷启动、功能、掉电和回滚测试；
- 候选静态差异仅包含批准范围，且 IMU 数据、硬超时、断连停止和输入释放测试全部通过；
- 用户在看到最终风险和恢复步骤后，明确授权具体目标、具体镜像哈希和具体刷写动作。

在此之前，所有生成镜像继续带 `NON_FLASHABLE`/`flash_allowed=false`，程序不暴露 DFU 写入入口。

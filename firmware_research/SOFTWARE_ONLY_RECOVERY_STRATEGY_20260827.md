# R08 不拆机的软件恢复结论（2026-08-27）

## 结论

在“不拆戒指、不接 UART/SWD/量产测试点”的约束下，当前 R08 只能证明存在**依赖原应用仍能启动的软件恢复**，不能证明存在应用失效后仍可进入的 BLE Bootloader/DFU 救砖模式。

因此，当前 292 字节 IMU 候选仍为 `NON_FLASHABLE`。软件试运行机制可以降低功能运行时的风险，却无法覆盖安装过程中断电、Bootloader 搬运失败、镜像头错误或应用启动失败。

## 哈希锁定的静态证据

证据对象是精确原厂镜像：

- 文件：`RT08_3.10.48_260309.bin`
- SHA-256：`c205290a7fcbc816b6be8d40f3e74d533551e0e7f2ebed9090a5d3b1c5ab613b`

`scripts/analyze_rt08_software_recovery.py` 对下列事实进行逐字节和调用目标校验：

1. `SystemInit` 在 `0x00826666` 调用 ROM `check_hci_mode_flag`，说明芯片启动早期存在 HCI/量产模式旁路。
2. 整个应用镜像没有调用 ROM `set_hci_mode_flag`，所以没有发现可由当前应用请求该旁路的软件入口。
3. 整个应用镜像没有调用 ROM `dfu_check_ota_mode_flag`，说明 SDK 的 `SUPPORT_NORMAL_OTA` 启动前 BLE OTA 分支没有编入 R08。
4. 镜像中保留了本地 `dfu_switch_to_ota_mode`：它设置 AON OTA 标志并以原因 `0xD3` 复位；但没有找到指向它的精确 Thumb `BL` 或 LDR literal 函数指针引用。这个“没有静态引用”不能排除理论上的计算型间接调用，但不足以建立恢复路径。
5. 官方 QRing DFU 完成处理在 `0x0082D6B8` 调用 `dfu_fw_reboot`。它属于正常应用代码，因此必须先让应用、BLE 栈和自定义 DFU 服务成功启动。

复核命令只读文件，不连接戒指：

```powershell
python firmware_research\scripts\analyze_rt08_software_recovery.py `
  research_artifacts\firmware\RT08_3.10.48_260309.bin
```

## 软件试运行能覆盖什么

候选补丁不修改 `SystemInit`、向量入口或任务启动链。唯一 hook 位于正常运行后的 `A1` 命令分派路径 `0x008280F6`，功能默认休眠，只有收到 `A1 09 01` 才启动，并有 12 秒固件硬超时、断连停止和主机 stale 急停。

如果补丁应用仍能启动，复位或断电重启后功能不会自动再次运行；官方 QRing DFU 也可在应用 BLE 服务正常时覆盖回精确原厂镜像。这属于**运行时隔离和应用级恢复**，不是自动固件回滚。

它不能覆盖：

- OTA 暂存写入或 Bootloader 搬运时掉电；
- 镜像头、入口、长度或校验处理错误导致无法启动；
- Bootloader/Flash 本身异常；
- 应用无法启动，因而官方自定义 DFU 服务也不存在。

## 不拆机的可执行替代路线

达到“可靠可刷”仍需下面两条中的至少一条：

1. **借到或由厂商提供一枚完全相同硬件 `RT08_V3.1` 的测试戒指。**先验证原厂包可安装并恢复，再刷候选，完成重复冷启动、断连、超时、充电盒复位和受控升级中断测试。用户已经说明不会购买第二枚，所以这不是当前默认路线，只保留为外借/厂商样机选项。
2. **由厂商提供工厂返修/重刷服务，或提供与该硬件匹配的签名自定义固件。**这可以替代用户自行接触测试点，但必须取得可实际执行的服务承诺或工具流程，不能只依赖口头说明。

只在当前唯一戒指上增加“确认按钮、试运行命令或看门狗”不能把安装阶段风险降为可恢复，因此不能单独满足可靠刷写门槛。

QRing App 资源中确认存在“客服中心/问题反馈”，反馈正文上限 200 字。可直接提交下面这段，不需要上传固件、日志、账号信息或 token：

> 设备R08_9C07，硬件RT08_V3.1，固件RT08_3.10.48_260309。请确认：若OTA后无法启动，是否支持不拆机进入Bootloader/DFU恢复？是否可返厂重刷？能否提供同硬件签名固件或测试样机？请给出具体操作或服务流程。

合格答复必须包含可执行的按键/充电盒/BLE 进入步骤、返厂受理方式或可验证的签名镜像交付流程之一；只回复“支持升级”“恢复出厂设置”或“重连 App”不能证明应用失效后的恢复能力。

## 当前决定

- 不再把拆机、测试点、UART 或 SWD 作为用户可执行路线。
- 继续保留并测试软件故障隔离机制。
- 在外借同硬件测试设备或厂商恢复承诺到位前，不向当前戒指发送任何 DFU 写命令。
- `flash_authorized=false`。

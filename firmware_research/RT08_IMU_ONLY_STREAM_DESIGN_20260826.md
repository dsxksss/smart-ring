# RT08 IMU-only 连续滚动离线设计（2026-08-26）

## 目标与边界

目标是在不启动光学 PPG/血氧通道的前提下，将 LIS3DH 的姿态样本以 10～20 Hz 发送给 Windows，用于带死区、速度上限和松手停止的连续滚轮。该设计不假设戒指存在连续触摸坐标，也不把 Windows 端插值描述为真实触摸跟踪。

当前只有一枚戒指，尚无已验证的 Boot ROM/UART/SWD 恢复路径。因此本文记录已经实现的离线候选架构、协议和验证门槛，不授权刷入实验固件。构建器只在显式传入 `--allow-unverified-output` 时写出带 `NON_FLASHABLE` 名称的审计文件，并始终报告 `flash_allowed=false`。

## 已确认的可复用链

| 作用 | 地址/值 | 已确认事实 |
| --- | --- | --- |
| 25 Hz FIFO 配置 | `0x00832D06 -> 0x00832D22` | `CTRL_REG1=0x37`、FIFO enable、stream mode |
| 50 Hz INT1 待机检测 | `0x008335FC -> 0x0083368C` | 高通、INT1 三轴正向阈值、FIFO 关闭 |
| FIFO 批读 | `0x00832F9C` | 读 `FIFO_SRC_REG 0x2F`，最多 32 个 XYZ 样本 |
| RAM 样本消费 | `0x0083394E` | 从 `0x0020BF70` 附近环形缓冲取 XYZ |
| RAM 生产者计数 | `0x0020BFA8` | 16 位字节计数；每个新 XYZ 前进 6，100 ms 不变化可判定没有新样本 |
| 现有通知出口 | `0x0082E974` | 发送 16 字节 Nordic UART 通知 |
| 现有校验 | `0x0082AC00` | 计算前 15 字节的末字节校验 |
| IMU 唤醒事件 | `0x00833A7C -> 0x0082D408(2)` | 生成实测 `02 02 00 ... 04` |
| A1 三轴构包片段 | `0x00827E62..0x00827EDA` | 调用 `0x0083394E`，构造并发送 `A1 03` |

现有 read timer 状态机也已经恢复出活动闭环：`0x0020BF80` 创建时 repeat=`1`；INT1/活动路径在 `0x00833C88` 设置状态 `+5`，`0x00833822` 配置 25 Hz FIFO 并以 `800` 重启 timer；后续普通周期在 `0x0083386A` 调用 `0x00832F9C` 排空 FIFO；状态 `+4` 在 `0x008337FC` 停止读取。新的 IMU 通知任务应复用这段原厂采样生命周期，而不是另建第二套并发 FIFO 生产者。

现有 `A1` 路径不能直接提频：`0x00827DAA` 的公共尾部一次发送 `A1 01..05`，而 `A1 04 04` 会启动光学测量并点亮 LED。IMU-only 方案必须绕开这条五通道公共打包链。

## 推荐状态流程

```text
原厂 INT1 待机
  -> 戒指敲击/双击产生 02 02
  -> Windows 收到唤醒事件
  -> Windows 写入新的 IMU_STREAM_START 命令
  -> 固件配置 25 Hz FIFO，并启动独立 100 ms 通知 timer
  -> 发送 10 Hz IMU-only 包，最长 12 秒；Windows 每 8 秒续期
  -> Windows 写 IMU_STREAM_STOP，或固件硬超时/故障停止
  -> 停止独立 timer，清空流状态，恢复原厂 INT1 待机配置
```

由 Windows 在收到 `02 02` 后显式启动流，比“每次敲击都由戒指自动跑固定窗口”更节电，也能避免未连接电脑时无意义地保持高频 BLE 活动。当前候选采用 12 秒硬超时和 8 秒续期，不能依赖 Windows 正常退出。

## 候选命令与通知格式

实现选择原厂 `A1` 处理器中已经确认的无效子命令 `0x09` 作为控制入口，不复用会点亮光学 LED 的 `A1 04`。`A2` 只用于新通知：

```text
A1 09 01 00 ... checksum   IMU_STREAM_START / RENEW
A1 09 00 00 ... checksum   IMU_STREAM_STOP
A2 10 ... checksum         IMU-only 通知
```

候选 IMU-only 通知仍为 16 字节，并沿用 `0x0082AC00` 校验：

| 字节 | 含义 |
| --- | --- |
| 0 | `0xA2` |
| 1 | `0x10`，IMU 样本版本 1 |
| 2 | 8 位递增序号 |
| 3 | flags：valid/stale/FIFO overflow/ending |
| 4..5 | X，little-endian `int16`，保持 RTL8762E 原生半字存储顺序 |
| 6..7 | Y，little-endian `int16` |
| 8..9 | Z，little-endian `int16` |
| 10 | 读取时 FIFO 样本数 |
| 11 | 自上一包以来丢弃的旧样本数 |
| 12..13 | 样本年龄或采样 tick；时基确认前保留为 0 |
| 14 | 保留，必须为 0 |
| 15 | 现有前 15 字节校验 |

序号和 stale/overflow 标志用于让 Windows 区分“手没动”和“数据已经停止”。不能在没有新样本时无限重复最后姿态，否则会造成松手后继续滚动。

## 采样与通知节拍

- LIS3DH 保持已确认的 25 Hz FIFO 配置，不直接把待机 `0x47` 配置当成连续流。
- 第一版通知上限设为 10 Hz；离线和功耗验证通过后再允许 20 Hz。
- 每个通知 tick 调用原厂 `0x0083394E` 取得最新样本，并比较 `0x0020BFA8` 的生产者字节计数。25 Hz 下每 100 ms 应至少产生两个样本；计数不变即发送一次 stale 状态并立即停止。
- 环形区容量阈值为 `0x1EC` 字节（82 个 XYZ 样本），而 16 位计数每个样本前进 6；在 100 ms 窗口内不可能完整绕回同一值，因此相等判断不会把正常满圈误判为停滞。
- 当前 FIFO level、dropped 和 age 字段保留为 0；在恢复出可靠统计前不伪造精度。
- 不允许通知 timer 快于传感器 ODR，也不允许在单个 tick 中把整个 FIFO 突发发送给 Windows。

## 强制停止条件

以下任一条件必须停止 IMU 流、释放 timer，并恢复原厂 INT1 待机配置：

1. 启动或最后一次续期后达到 12 秒硬超时；
2. 收到 `IMU_STREAM_STOP`；
3. BLE 断开（固件每个 tick 显式检查）；主机连续 250 ms 收不到有效通知时也会 fail-closed 并停止注入；
4. FIFO/环形缓冲在限定时间内没有新样本；
5. 配置或读取函数返回失败；
6. 固件进入充电、关机、升级或原厂测量状态。

停止函数必须设计为幂等：重复调用不会重复释放、不会遗留 timer，也不会保持 FIFO 或光学 LED。异常退出后不能留下持续通知或持续滚动。

## Windows 滚轮映射

Rust 端已经加入显式 `imu-stream` 子命令、候选包解码、fail-closed 跟踪器和滚轮映射。它先精确核对 `RT08_V3.1 / RT08_3.10.48_260309`，还要求 `--acknowledge-unverified-candidate`；默认只监听日志，必须额外传入 `--inject` 才会向 Windows 注入滚轮。校验错误、序号跳变、stale、overflow、ending、无效重力或 250 ms 无新数据都会发送停止、释放全部输入状态并断开。正常退出时发送停止失败也会作为错误返回，而不是静默成功。

Windows 端只在 IMU 包 valid 且序号连续时使用样本：

1. 唤醒后前 300～500 ms 建立佩戴中性姿态；
2. 用重力向量计算俯仰/横滚，不尝试估计绕重力轴的纯旋转；
3. 使用约 3～5° 死区，离开死区后把角度映射为有上限的滚轮速度；
4. 反向时先归零再加速，避免来回滑动时粘滞；
5. stale、丢包超时或 ending 到达时立即把滚动速度归零；
6. Windows 插值只负责平滑输出，日志必须保留真实样本频率和插值频率的区别。

## 实施前仍需恢复的固件事实

1. BLE 断开、充电、关机和原厂测量状态与候选 timer 并发时的所有停止来源；timer 参数单位已由 Realtek 官方资料确认为毫秒，最小精度 10 ms；
2. RTL8762E 双应用槽在版本相同情况下的选择规则，以及结构有效但运行时崩溃时是否有自动回退；
3. 整片 Flash 的 Bootloader、系统配置、OTA 元数据和应用之外的精确分区；
4. 独立 UART/MP 或 SWD 恢复路径、实际 PCB 测试点和可原样回写的双份完整备份；
5. 在第二枚同硬件设备或等价测试板上的刷写、失败启动和恢复演练。没有这些，不对刷写唯一戒指。

## 离线验证门槛

先运行只读锚点校验；它会验证官方镜像 SHA-256 和上述关键原始指令字节，不修改输入文件：

```powershell
python firmware_research\scripts\verify_rt08_imu_stream_anchors.py path\to\RT08_3.10.48_260309.bin
```

任何候选补丁都必须同时提供：

- 原厂镜像 SHA-256 `c205290a7fcbc816b6be8d40f3e74d533551e0e7f2ebed9090a5d3b1c5ab613b`；
- 每个修改地址的原始字节、修改字节、Thumb 反汇编和控制流理由；
- QRing 外层 `0x50` 容器长度与 sum32，以及 RTL8762E 内层头字段校验；
- 新状态机的启动、正常停止、超时停止、断连停止和重复停止测试；
- Windows 解码、序号跳变、stale、反向和停止延迟测试；
- `flashAuthorized=false`。在恢复路径验证前，候选文件必须明确标记为不可刷。

当前经逐指令复核的 patch 对象为 292 字节，SHA-256：

```text
0aeb8f7fd8ed84e642b38dadfa578d0185fd3aee96a55554ce2798c9a0faec0a
```

它占用 `0x00849B08..0x00849C2C`，尾部仍有 4 个零字节；离线候选整包 SHA-256 为 `d55458692d51ff4d21d385e61dfba34c8296934944fe3ad493f0dc07744ec1ac`。这两个哈希用于复现与审计，不表示允许刷写。callback 每个 tick 直接调用已定位的原厂连接检查函数，断连时会在读取 FIFO 和发送通知前进入统一停流路径，不等待 12 秒硬超时；未知的通知包装器返回语义不参与安全判断。

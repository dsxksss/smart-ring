# RT08 IMU-only 连续滚动离线设计（2026-08-26）

## 目标与边界

目标是在不启动光学 PPG/血氧通道的前提下，将 LIS3DH 的姿态样本以 10～20 Hz 发送给 Windows，用于带死区、速度上限和松手停止的连续滚轮。该设计不假设戒指存在连续触摸坐标，也不把 Windows 端插值描述为真实触摸跟踪。

当前只有一枚戒指，尚无已验证的 Boot ROM/SWD 恢复路径。因此本文只定义离线候选架构、协议和验证门槛，不授权生成或刷入实验固件。

## 已确认的可复用链

| 作用 | 地址/值 | 已确认事实 |
| --- | --- | --- |
| 25 Hz FIFO 配置 | `0x00830D06 -> 0x00830D22` | `CTRL_REG1=0x37`、FIFO enable、stream mode |
| 50 Hz INT1 待机检测 | `0x008315FC -> 0x0083168C` | 高通、INT1 三轴正向阈值、FIFO 关闭 |
| FIFO 批读 | `0x00830F9C` | 读 `FIFO_SRC_REG 0x2F`，最多 32 个 XYZ 样本 |
| RAM 样本消费 | `0x0083194E` | 从 `0x0020BF70` 附近环形缓冲取 XYZ |
| 现有通知出口 | `0x0082C974` | 发送 16 字节 Nordic UART 通知 |
| 现有校验 | `0x00828C00` | 计算前 15 字节的末字节校验 |
| IMU 唤醒事件 | `0x00831A7C -> 0x0082B408(2)` | 生成实测 `02 02 00 ... 04` |
| A1 三轴构包片段 | `0x00825E62..0x00825EDA` | 调用 `0x0083194E`，构造并发送 `A1 03` |

现有 read timer 状态机也已经恢复出活动闭环：`0x0020BF80` 创建时 repeat=`1`；INT1/活动路径在 `0x00831C88` 设置状态 `+5`，`0x00831822` 配置 25 Hz FIFO 并以 `800` 重启 timer；后续普通周期在 `0x0083186A` 调用 `0x00830F9C` 排空 FIFO；状态 `+4` 在 `0x008317FC` 停止读取。新的 IMU 通知任务应复用这段原厂采样生命周期，而不是另建第二套并发 FIFO 生产者。

现有 `A1` 路径不能直接提频：`0x00825DAA` 的公共尾部一次发送 `A1 01..05`，而 `A1 04 04` 会启动光学测量并点亮 LED。IMU-only 方案必须绕开这条五通道公共打包链。

## 推荐状态流程

```text
原厂 INT1 待机
  -> 戒指敲击/双击产生 02 02
  -> Windows 收到唤醒事件
  -> Windows 写入新的 IMU_STREAM_START 命令
  -> 固件配置 25 Hz FIFO，并启动独立 50/100 ms 通知 timer
  -> 发送 10～20 Hz IMU-only 包，最长 60 秒
  -> Windows 写 IMU_STREAM_STOP，或固件硬超时/故障停止
  -> 停止独立 timer，清空流状态，恢复原厂 INT1 待机配置
```

由 Windows 在收到 `02 02` 后显式启动流，比“每次敲击都由戒指自动跑 60 秒”更节电，也能避免未连接电脑时无意义地保持高频 BLE 活动。固件仍必须保留独立的 60 秒硬超时，不能依赖 Windows 正常退出。

## 候选命令与通知格式

建议使用尚未占用的新主命令 `0xA2`，不要复用 `A1 04`：

```text
A2 01 01 ... checksum   IMU_STREAM_START
A2 01 00 ... checksum   IMU_STREAM_STOP
A2 02 00 ... checksum   IMU_STREAM_STATUS（可选）
```

候选 IMU-only 通知仍为 16 字节，并沿用 `0x00828C00` 校验：

| 字节 | 含义 |
| --- | --- |
| 0 | `0xA2` |
| 1 | `0x10`，IMU 样本版本 1 |
| 2 | 8 位递增序号 |
| 3 | flags：valid/stale/FIFO overflow/ending |
| 4..5 | X，big-endian `int16` |
| 6..7 | Y，big-endian `int16` |
| 8..9 | Z，big-endian `int16` |
| 10 | 读取时 FIFO 样本数 |
| 11 | 自上一包以来丢弃的旧样本数 |
| 12..13 | 样本年龄或采样 tick；时基确认前保留为 0 |
| 14 | 保留，必须为 0 |
| 15 | 现有前 15 字节校验 |

序号和 stale/overflow 标志用于让 Windows 区分“手没动”和“数据已经停止”。不能在没有新样本时无限重复最后姿态，否则会造成松手后继续滚动。

## 采样与通知节拍

- LIS3DH 保持已确认的 25 Hz FIFO 配置，不直接把待机 `0x47` 配置当成连续流。
- 第一版通知上限设为 10 Hz；离线和功耗验证通过后再允许 20 Hz。
- 每个通知 tick 先排空 FIFO/RAM 队列，只保留最新有效样本，旧样本计入 dropped 字段，避免积压造成明显延迟。
- 若 250 ms 没有新样本，发送一次 stale/ending 状态后立即停止流；具体阈值需要真机数据验证，但停止路径必须在首个候选中存在。
- 不允许通知 timer 快于传感器 ODR，也不允许在单个 tick 中把整个 FIFO 突发发送给 Windows。

## 强制停止条件

以下任一条件必须停止 IMU 流、释放 timer，并恢复原厂 INT1 待机配置：

1. 启动后达到 60 秒硬超时；
2. 收到 `IMU_STREAM_STOP`；
3. BLE 断开或连续通知失败；
4. FIFO/环形缓冲在限定时间内没有新样本；
5. 配置或读取函数返回失败；
6. 固件进入充电、关机、升级或原厂测量状态。

停止函数必须设计为幂等：重复调用不会重复释放、不会遗留 timer，也不会保持 FIFO 或光学 LED。异常退出后不能留下持续通知或持续滚动。

## Windows 滚轮映射

Rust 端已先加入候选包的纯解码与 fail-closed 跟踪器：`r08/src/protocol.rs` 的 `evaluate_imu_stream_packet` / `ImuStreamTracker` 会解析序号、flags、XYZ、FIFO 水位和 dropped 计数；校验错误、序号跳变、stale、overflow、ending 或 250 ms 无新数据都会返回停止原因。该代码尚未接入 BLE 控制命令或滚轮注入，因此不会改变当前戒指行为。

Windows 端只在 IMU 包 valid 且序号连续时使用样本：

1. 唤醒后前 300～500 ms 建立佩戴中性姿态；
2. 用重力向量计算俯仰/横滚，不尝试估计绕重力轴的纯旋转；
3. 使用约 3～5° 死区，离开死区后把角度映射为有上限的滚轮速度；
4. 反向时先归零再加速，避免来回滑动时粘滞；
5. stale、丢包超时或 ending 到达时立即把滚动速度归零；
6. Windows 插值只负责平滑输出，日志必须保留真实样本频率和插值频率的区别。

## 实施前仍需恢复的固件事实

1. `0x0020BF80` read timer 的绝对时间单位，以及活动阶段最终停止请求的所有来源；
2. 环形缓冲生产/消费索引和溢出规则，确保“取最新样本”不会破坏原厂计步/敲击算法；
3. 可容纳新状态和构包逻辑的代码空间，以及所有 Thumb 分支距离和重定位；
4. RF03 镜像是否有未识别签名、分区边界或运行时完整性检查；
5. 独立恢复路径。没有这一项，不对刷写唯一戒指。

先运行只读锚点校验；它会验证官方镜像 SHA-256 和上述关键原始指令字节，不修改输入文件：

```powershell
python firmware_research\scripts\verify_rt08_imu_stream_anchors.py research_artifacts\firmware\RT08_3.10.48_260309.bin
```

任何候选补丁都必须同时提供：

- 原厂镜像 SHA-256 `c205290a7fcbc816b6be8d40f3e74d533551e0e7f2ebed9090a5d3b1c5ab613b`；
- 每个修改地址的原始字节、修改字节、Thumb 反汇编和控制流理由；
- RF03 `0x50` 容器长度与 sum32 校验；
- 新状态机的启动、正常停止、超时停止、断连停止和重复停止测试；
- Windows 解码、序号跳变、stale、反向和停止延迟测试；
- `flashAuthorized=false`。在恢复路径验证前，候选文件必须明确标记为不可刷。
